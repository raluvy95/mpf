# Commit and release conventions

- Use Conventional Commits for new commits: `type: short imperative description` (optionally `type(scope): ...`).
- Use `feat:` for features, `fix:` for bug fixes, and `docs:`, `test:`, `refactor:`, or `chore:` where appropriate.
- Mark breaking changes with `!` after the type/scope and describe them in a `BREAKING CHANGE:` footer.
- Follow Semantic Versioning for releases: breaking changes bump MAJOR, features bump MINOR, and fixes bump PATCH. Other commit types do not imply a version bump by themselves.
- Base the next version on the latest existing tag (check `git tag`), never on unreleased commits. Only the highest bump
  since that tag applies, so with `v1.0.3` as the latest tag, any number of pending `feat:` commits means `1.1.0`, not `1.2.0`.
- These are naming and versioning conventions. Only Release Please creates tags and GitHub Releases
  (merging its release PR publishes the release and AppImage). Never create or push tags manually.
- Do not commit local virtual environments such as `.venv/`.
- Always pull and resolve upstream changes before creating a commit.
- Never push to GitHub from this environment; tell the user when a manual push is needed.

# Project rules

- Do not keep a TODO or progress-log file. History lives in git and `CHANGELOG.md` (generated by release-please).
- Before committing, run `.venv/bin/python -m pytest`, `.venv/bin/python -m ruff check .`, and `.venv/bin/python -m mypy mpf.py mpf_core`.
- Do not pin `yt-dlp`: keep it out of `constraints.txt` (remove its line after regenerating from `pip freeze`) and leave
  `requirements.txt` without an upper bound. YouTube breaks old releases, and mpv and MPF both use the `yt-dlp` on `PATH`.
- Test audio code, including the visualizer, with synthetic signals only. Never read, decode, copy, or analyze the user's
  music (for example `~/Music`) or capture their system audio for testing; delete any scratch audio you generate.
- Verify audio and playback changes end to end where possible (for example `pw-play --target 0` into PipeWire, which is
  silent, plus the real `pw-record` command), not only with in-memory arrays. The `pw-record` stream format once hid a bug.
